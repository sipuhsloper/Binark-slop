# Binark

**Binark** — это нативный кроссплатформенный конвертер текста, целых чисел и
файлов в их двоичное (бинарное) представление и обратно.

Проект написан на **C17** с использованием **GTK 4** и **libadwaita**. Приложение
построено как интеграция с GNOME (HIG / Adwaita), а вся логика преобразований
реализована самостоятельно без сторонних конвертеров и внешних программ.

## Возможности

- **Текст:**
  - кодирование UTF-8 текста в бинарное представление (байты, биты);
  - декодирование бинарной последовательности обратно в UTF-8;
  - кодирование/декодирование текста в **Base64** и **Base32** (RFC 4648);
  - поддержка русского языка, эмодзи и других Unicode-символов;
  - строгая обработка ошибок: неполный байт, недопустимый символ,
    некорректный UTF-8, нулевой байт;
  - автоматические переносы строк и разделители байт;
  - настраиваемое число байт на строку.
- **Целые числа:**
  - конвертация между основаниями **2–12, 16, 32 и 64** (двоичная, восьмеричная,
    десятичная, шестнадцатеричная, base32, base64 и другие);
  - поддержка отрицательных чисел и нуля;
  - произвольная точность (большие числа, без потерь);
  - поддержка префиксов `0b`, `0o`, `0x` (с проверкой соответствия основанию);
  - опция верхнего регистра латинских цифр A–Z (для оснований до 36 включительно).
- **Файлы:**
  - потоковое кодирование/декодирование файла;
  - отображение имени, размера и типа файла;
  - индикатор прогресса и отмена операции;
  - проверка свободного места и атомарное сохранение результата;
  - компактный формат без разделителей и сохранение исходного вида с разделителями;
  - результат сохраняется только при успешном завершении.
- **Настройки и интерфейс:**
  - тема (системная / светлая / тёмная);
  - форматирование (разделители, байтов на строку, компактный формат файлов);
  - поведение (автокопирование результата, история операций);
  - история последних операций без содержимого файлов и текста;
  - функция поиска по командам и истории;
  - диалоги настроек (libadwaita) и «О программе» (version, технологии, лицензия).

## Требования

- Linux (рекомендован дистрибутив семейства GNU/Linux);
- GTK 4 и libadwaita (рантайм-пакеты);
- GLib / GIO / GSettings;
- доступ к системной теме (опционально, для темы «Системная»).

## Сборка

```bash
git clone https://github.com/sipuhsloper/Binark-slop.git
cd Binark
make
```

## Запуск

```bash
make run
```

## Установка и удаление

```bash
make install   # устанавливает в ~/.local (user XDG)
make uninstall
```

## Тесты

```bash
make test
```

Скрипт собирает и запускает модульные тесты:
текстовые конвертеры (ASCII, UTF-8, эмодзи, форматирование, ошибки), числовые
конвертеры (основания, знаки, большие числа, ошибки) и файловые конвертеры
(циклические, пустые файлы, повреждённые данные, отмена, большие файлы).

## Горячие клавиши

| Сочетание           | Действие                          |
| ------------------- | --------------------------------- |
| `Ctrl` + `Enter`   | Преобразовать                      |
| `Ctrl` + `C` / `Ctrl` + `V` | Копирование / вставка результата |
| `Ctrl` + `L`       | Очистить поле                       |
| `Ctrl` + `O`       | Открыть файл (режим файлов)        |
| `Ctrl` + `Shift`+`S` | Сохранить результат               |
| `Ctrl` + `,`       | Открыть настройки                   |

Символы `Ctrl` (`<Control>`) в GTK-accelerators записываются латиницей.

## О проекте

Проект Binark создаётся в процессе автоматизированной разработки с активным
участием нейросетевых моделей (AI/LLM). Часть исходного кода, тестов, документации
и метаинформации сгенерирована нейросетями, поэтому проект стоит рассматривать как
**«нейрослоп» (neural slop / AI-generated content)** — подготовленный ИИ-контент,
не являющийся, при классическом чтении, продуктом дизайна конкретной команды.

При этом всё преобразовательное ядро, архитектура и интеграция с GTK/libadwaita
проектируются и проверяются человеком; нейросеть выполняла генерацию и
первичную реализацию, а человек — контроль качества, тестирование и правки.

Автор проекта: **SipuhSloper**.

## Ограничения

- Дробные числа не поддерживаются (только целые).
- Обработка очень длинных чисел может быть медленной на больших длинах (алгоритм
  повторного деления).
- В текстовом режиме нулевые байты не допускаются.
- При отмене файла промежуточные временные файлы удаляются; результат прежнего
  состояния не перезаписывается.
